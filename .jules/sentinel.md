## 2026-10-17 - Prevent XSS in dynamic a href creation
**Vulnerability:** The application was vulnerable to Cross-Site Scripting (XSS) due to dynamic creation of `<a>` tags and direct execution of their `.click()` method using unsanitized `audioUrl` inputs retrieved from an API. Because it bypassed Angular's `[href]` attribute sanitization, a malicious API could return a `javascript:alert(1)` payload that would execute.
**Learning:** Bypassing template binding via explicit document element creation (e.g., `document.createElement('a')`) completely circumvents standard framework (Angular) XSS protections. Furthermore, attempting to use the `new URL()` constructor to validate protocol paths introduces the risk of breaking functionality that depends on relative paths.
**Prevention:** Always validate URLs explicitly when dynamically evaluating properties that accept javascript or other potentially executable protocols. Use regular expressions (e.g. `/^(javascript|data|vbscript):/i.test(url.trim())`) to restrict malicious schemas without breaking valid relative path inputs.
